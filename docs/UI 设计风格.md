# VibeGo UI 设计风格

VibeGo 是一个移动端优先的开发工具。新增界面应像同一个工作台的一部分，不要做成风格独立的小产品。

## 1. 设计侧重点

### 移动端优先

先在手机竖屏上决定信息和操作的优先级，再扩展到桌面端。

- 重要信息和常用操作直接显示。
- 手机页面重新组织内容，不把桌面页面简单缩小。
- 次要信息和低频操作放进详情或底部弹层。
- 优先考虑单手操作，主要操作放在容易触达的位置。

### 桌面端追求效率

桌面端沿用移动端的结构和操作方式，只增加信息量和快捷操作。

- 用更宽的空间展示详细信息，而不是单纯放大控件和留白。
- 文件、Git、终端、进程、远程桌面等工作区尽量使用全部空间。
- 同一个功能在手机和桌面上保持相同的名称、状态和操作逻辑。

### 内容和操作优先

用户打开 VibeGo 是为了完成任务，不是浏览介绍。

- 页面中心应留给文件、代码、终端、远程画面和数据。
- 当前所在位置、当前选中项和当前运行状态要容易看懂。
- 减少说明文字和装饰，让用户尽快进入操作。

## 2. 页面框架

VibeGo 的页面都运行在同一个应用框架中。框架分为顶部区域、中部内容、任务栏和四角操作区。页面只负责主体内容和框架允许自定义的部分，不自行重做外层导航。

### 顶部区域

顶部区域用于切换当前任务内部的内容，例如多个文件、终端会话、Git 的变更与历史、设置分类以及列表与详情。

- 中间是可以横向滚动的标题或标签区域。
- 左右两端是固定操作区，不随中间标签一起滚动。
- 左侧通常用于返回、关闭当前页或切换当前页面的主要视图。
- 右侧通常放刷新、新建、编辑等当前页面的常用操作。
- 没有页面自定义时，框架显示默认标签栏，负责已打开文件等内容的切换。
- 页面需要自己的分类或会话切换时，可以接管顶部区域，但不能再叠加一层同级标签栏。

顶部区域处理的是“当前任务里面看什么”，不是切换整个工作区。

### 中部内容

中部是页面主体，占满框架剩余空间，用于文件、代码、终端、列表、设置或远程画面。

页面可以在主体内增加与内容直接相关的工具栏，例如文件搜索和排序，但不要重复框架已经提供的页面切换、返回和全局菜单。

### 任务栏

任务栏类似 Windows 任务栏，用于切换独立打开的工作区和工具页面。

- 一个任务项可以代表首页、一个文件夹工作区、一个工具页面或设置页。
- 文件夹工作区可以在同一个任务项中展开文件、Git 和终端入口。
- 当前任务使用主题色突出显示。
- 新建页面、排序、关闭当前任务、关闭其他任务等行为由框架统一提供。
- 普通页面沿用默认任务栏。只有页面本身确实存在需要长期显示的框架级任务时，才替换任务栏内容。

顶部区域切换当前任务内部的内容，任务栏切换当前正在使用的任务。不要把普通页内标签放进任务栏，也不要用顶部标签代替独立工作区。

### 四角操作区

框架保留四个固定操作位，中心的标签和任务项可以滚动。这里的“四角”指四种固定职责，桌面端不需要照搬手机上的物理位置。

| 固定位置 | 默认职责 | 页面可设计的内容 |
| --- | --- | --- |
| 顶部左侧 | 返回列表或关闭当前页面 | 当前页面的返回、列表切换或主视图入口 |
| 顶部右侧 | 刷新、编辑等当前页操作 | 少量高频操作，例如新建、连接、刷新 |
| 任务栏起点 | 打开 VibeGo 主菜单 | 主菜单按钮由框架固定，页面的低频操作可以加入菜单 |
| 任务栏末端 | 全屏等框架操作 | 可以替换为需要始终可用的页面级操作 |

高频且与当前内容直接相关的操作放顶部右侧；低频操作放进主菜单，不要把顶部塞满按钮。

### 移动端和桌面端的重排

框架在移动端和桌面端保持相同职责，只改变摆放方式。

- 移动端顶部区域横向显示，任务栏放在底部，四角操作区对应屏幕四角。
- 桌面端顶部区域仍位于主体上方，顶部两侧操作保持不变；任务栏改为左侧竖栏。
- 桌面左侧栏顶部是主菜单，中间是任务项和新建入口，底部是全屏或页面提供的固定操作。
- 页面不应为手机和桌面分别实现两套导航逻辑，框架会负责这些元素的位置变化。

## 3. 整体风格

界面应当安静、紧凑、清楚，接近 IDE 和终端工具的感觉。

- 主要使用两层背景和细边框区分区域。
- 亮色只用于当前项、主要操作和状态提示。
- 普通内容不使用明显阴影，浮层只使用轻微阴影。
- 普通控件使用小圆角，大圆角只留给弹层和少数独立区域。
- 信息可以密集，但排列必须整齐，主次必须明确。

不要使用大标题、宣传文案、渐变背景、装饰图片、发光色块和无意义动画。不要把每块内容都做成悬浮卡片，也不要在卡片里继续嵌套卡片。

## 4. 按钮

按钮的整体风格是紧凑、克制、工具化。不要让所有按钮都很抢眼。

### 工具按钮

刷新、关闭、编辑、删除、全屏等常见操作使用 Lucide 图标按钮。

- 外形以小尺寸方形为主，使用小圆角。
- 默认状态保持低调，悬停或选中时再改变背景和颜色。
- 同一排工具按钮保持相同大小和间距。
- 不为常见图标再添加冗长文字。

### 主要按钮

主要按钮使用主题主色和实心背景，用于当前页面最重要的下一步，例如登录、打开、连接、保存。

- 一个区域内只保留少量主要按钮。
- 文案直接使用动作词，不写解释性句子。
- 不要把普通操作也做成主要按钮，否则页面会失去重点。

### 次要按钮

大多数操作使用次要按钮。

- 使用普通面板背景或透明背景，加细边框。
- 颜色和对比度低于主要按钮。
- 可以使用图标加短文字，也可以只用图标。

### 危险按钮

删除、停止、清空等操作使用红色文字或浅红背景。

- 页面中的危险按钮保持克制，不使用大面积纯红色。
- 实心红色只用于最后一步的明确确认。

### 按钮组

- 同一组按钮保持相同高度和视觉重量。
- 模式切换使用并排的分段按钮，当前模式要明显。
- 不把所有选项都做成独立的圆角胶囊。

## 5. 信息和容器

页面本身是工作区，不需要再套一层大卡片。

- 大区域通过背景变化、边框和留白分开。
- 文件、提交、端口、进程等重复内容优先使用列表。
- 卡片只用于相对独立、需要整体识别的一组内容。
- 当前项使用轻微的主题色背景或边框，不使用强烈的整块高亮。
- 主名称最明显，时间、路径、大小和说明降低对比度。

手机上先显示名称、状态和主要操作；桌面端再补充更多信息列。

## 6. 文字和颜色

文字层级保持简单：主文字、次要文字、状态文字。

- 工具页使用小而紧凑的标题，不使用展示型大标题。
- 路径、命令、提交编号和 PID 等内容使用等宽字体。
- 说明文字只在操作含义不清楚时出现，并尽量简短。
- 主题主色表示当前项、焦点和主要操作。
- 红色表示错误或危险，绿色表示成功或正常运行，橙色表示警告。
- 状态色只表达状态，不用于装饰。

## 7. 输入和选择

输入控件应与工具界面融为一体，不做成突出的大表单。

- 输入框使用普通背景、细边框和小圆角。
- 获得焦点时只加强边框或主题色，不增加夸张效果。
- 同一行的输入框、选择器和按钮保持相同高度。
- 开关用于开和关，分段按钮用于少量模式切换，下拉菜单用于较多选项。
- 搜索框放在工具栏中时，可以占满剩余空间，与工具栏融为一体。
- 开关保持小巧，开启时使用主题主色，关闭时使用中性颜色。
- 复选框使用方形，选中后填充主题主色。
- 设置项保持简洁，不为每一项设计不同的排列方式。

## 8. 工具栏、标签和路径

工具栏是一条紧凑的操作带，不是页面标题区。

- 使用面板背景和底部细边框。
- 操作以图标按钮为主，相关操作放在一起，不同组之间用细分隔线隔开。
- 搜索、选择模式等临时状态直接替换工具栏内容，不另外弹出一块区域。
- 加载中的工具按钮保持原位，只让图标旋转，避免工具栏跳动。

标签保持单行、紧凑，不做成一排胶囊按钮。

- 未选中标签使用透明背景和次要文字色。
- 当前标签使用面板背景、主题色文字和主题色边框。
- 关闭按钮弱化显示，不和标签标题抢视觉重点。
- 标签过多时横向滚动。

路径导航与工具栏放在同一层级。当前路径使用轻微主题色背景，父级路径保持普通文字；路径过长时横向滚动，不换成多行。

## 9. 列表项和状态标签

列表是 VibeGo 展示重复信息的默认方式。

- 普通列表项横向铺满，通过分隔线区分，不是一项一张卡片。
- 相对独立、内容较多的项目可以使用细边框和小圆角，但仍保持紧凑。
- 当前项使用浅色主题背景或主题色边框。
- 悬停状态只做轻微背景或边框变化。
- 图标、名称、说明、状态和操作保持固定顺序，避免每一行各自排版。

状态标签应当小而轻，只作为内容的补充。

- 普通标签使用细边框和次要文字色。
- 错误、成功和警告标签使用对应状态色的浅背景。
- 标签文字保持简短，不把说明句子塞进标签。
- 标签不要比主内容更醒目，也不要把所有分类都做成彩色胶囊。

## 10. 菜单和操作单

桌面端菜单使用小型浮层，手机端同类操作优先使用底部操作单。

- 菜单使用面板背景、细边框、小圆角和轻微阴影。
- 菜单项横向铺满，左侧图标，右侧短文字。
- 菜单分组之间使用细分隔线，不用多个卡片分组。
- 当前选项使用主题色文字或轻微背景。
- 危险操作放在菜单末尾，并使用红色。

手机底部操作单使用较大的纵向菜单项，顶部可以显示短标题，底部留出安全区域。不要把桌面小菜单直接缩小后放到手机上。

## 11. 对话框

对话框用于需要用户明确决定的操作，内容应当短而直接。

- 手机上从底部出现，桌面端居中显示。
- 使用面板背景、细边框和轻微阴影。
- 标题简短，说明使用次要文字色。
- 手机上操作按钮纵向排列并占满宽度；桌面端按钮放在右下方。
- 取消按钮保持中性，确认按钮使用主题主色，危险确认使用红色。
- 不在对话框中继续嵌套卡片和多层标题。

## 12. 加载、空状态和反馈

状态反馈尽量出现在正在操作的区域内，不打断整个工作区。

- 短加载使用旋转图标；整块内容加载时使用居中的小图标或简短文字。
- 空状态使用低对比度图标和一句短说明，不需要大卡片或长篇引导。
- 错误使用浅红背景、红色文字和细边框，放在出错内容附近。
- 成功、失败等一次性结果使用顶部通知，不在页面中长期保留提示条。
- 上传或长任务的进度条保持细窄，颜色使用主题主色。

通知使用小图标、短标题和必要的补充说明。桌面端放在右上方，手机端放在顶部并避开安全区域。

## 13. 手机和桌面的区别

手机端以单列、列表和底部弹层为主，重要操作直接显示并靠近底部。

桌面端可以增加侧栏、标签、信息列和悬停操作，但不要改变手机端已经建立的操作逻辑。

简单页面可以居中显示；文件、Git、终端、进程和远程桌面等工作页面应铺满可用空间。
